## 1. 背景与目标

sub2Image 目前的生成体验以"画廊任务流 + Agent 对话流"为主，产出是线性列表。无限画布提供第三种工作方式：一块可以自由平移缩放的空间，把文本、图片、视频作为**节点**摆放、连线、迭代生成，适合多素材编排、参考图驱动的图生视频、以及围绕一个主题的发散创作（对标 Flora / Krea Nodes 的节点式 AI 画布形态）。

V1 目标：

1. 用户可以从**画廊**和 **Agent 对话**进入画布，创建/管理多个画布文档。
2. 画布支持三种节点类型：**文本节点、图片节点、视频节点**，节点可拖拽、连线、悬浮出各自的功能菜单。
3. 选中可生成的节点后，弹出**复用全局聊天组件**的输入框（在现有聊天组件的类型机制上新增 `canvas` 类型），走现有任务系统完成图片/视频生成，结果回填到节点。
4. 画布文档持久化到本地 IndexedDB，刷新/重启不丢失，生成中断可恢复。

`拓展走向.md` 已把"多图拼接和自由画布"列为阶段 6 待评估项，本文档即该方向的第一版落地。

## 2. 名词定义

- **画布文档（CanvasDocument）**：一块无限画布及其全部节点、连线，对应截图中的"无限画布 2"。
- **节点（CanvasNode）**：画布上的最小内容单元，V1 有 text / image / video 三种 kind。
- **空节点**：已创建但尚无内容的图片/视频节点（如截图中的"空视频节点"），是生成的入口。
- **连线（CanvasEdge）**：节点间的有向连接，V1 语义为**生成输入引用**（上游节点作为下游生成的参考素材）。
- **画布聊天（canvas tool）**：全局聊天组件的新类型，作用域绑定到"某画布文档的某节点"。

## 3. V1 范围

### 包含（P0）

- 画布文档的创建、重命名、删除、列表管理
- 无限视口：平移、滚轮/双指缩放、缩放控件、适配视图、点阵背景
- 三种节点的创建（画布右键/双击菜单、底部工具栏、从画廊/对话添加、本地上传、拖拽/粘贴入画布）
- 节点拖拽、多选/框选、删除、复制
- 节点连线（图片 → 图片/视频，文本 → 图片/视频）
- 节点悬浮功能菜单（三种类型各自的功能点，详见 §7）
- 选中节点弹出画布聊天输入框，图片生成 + 视频生成（文生/图生）闭环
- 生成任务绑定节点：生成中 / 成功 / 失败三态展示，失败可重试
- 画布文档本地持久化（IndexedDB）、图片/视频资产引用保护（防 GC）

### 不包含（V1 之后）

- 画布文档云同步（依赖 CLOUD_STORAGE_PLAN 扩展 `/cloud-api/canvases`，届时先更新该计划文档）
- 撤销/重做（P1，见 §14）
- 多人协作、分享链接
- 画布整体导出为长图/视频
- 节点分组、批注、手绘笔
- 移动端触屏的完整编辑体验（V1 保证移动端可浏览、可平移缩放）

## 4. 入口与导航

### 4.1 路由方案

新增独立路径分支，**不扩张 `AppMode`**（`AppMode` 与 `TaskRecord.sourceMode`、persistence merge、Header 二态开关深度耦合，扩张连锁改动大且刷新时未知值会被压回 gallery）。参照 `ExtensionWorkspace/extensionRoutes.ts` 的范式：

- `/app/canvas` — 画布文档列表页
- `/app/canvas/:docId` — 画布编辑页
- 新增 `src/features/canvas/canvasRoutes.ts`：`isCanvasPath` / `parseCanvasRoute` / `navigateToCanvas(docId?)` / `leaveCanvas()`
- `App.tsx` 顶部增加第三个路径分支（与 `isExtensionPath` 并列），该分支内按需挂载 `Toast`、`ConfirmDialog`、画布自己的 Modal 与聊天组件

### 4.2 入口位置

| 入口 | 位置 | 行为 |
| --- | --- | --- |
| 画廊头部 | `GalleryHeaderControls.tsx` 图标按钮排（"拓展工作区"旁） | 进入画布列表页 |
| 画廊批量操作条 | `GallerySelectionActionBar.tsx` | "添加到画布"：选中任务的产出图加入指定/新建画布并跳转 |
| 单图操作 | `ImageContextMenu.tsx` / `Lightbox.tsx` / `DetailModal.tsx` | "加入画布" |
| Agent 对话 | 对话内任务卡（`AgentWorkspace` 中的 TaskCard 操作区） | "加入画布"：把该轮产出加入画布 |
| 移动端 | `Header.tsx` | 画布入口图标 |

"加入画布"需要一个轻量的**画布选择器弹层**（选择已有画布或新建，记住上次选择）。

### 4.3 画布列表页

卡片式列表：缩略预览（首个图片节点的缩略图或占位）、名称（可重命名）、节点数、更新时间；支持新建、删除（二次确认）。V1 不做搜索分页（数量预期 < 50）。

## 5. 画布基础交互

- **视口**：无限平移（空格/中键/手型工具拖拽，触控板双指），缩放范围建议 2%–400%，缩放以指针为中心；左下角控件：放大/缩小/适配视图/锁定画布/隐藏连线（对齐截图左下角控件组）。注意现有 `lib/viewportTransform.ts` 是为 Lightbox 写的（scale 钳制 [1,6] 且强制内容充满视口），**不能直接复用**，无限画布视口由画布库提供。
- **选择**：单击选中（高亮描边，见截图绿色描边态）；框选多选（可参考 `hooks/useDragSelect.ts` 的交互标准）；`Delete/Backspace` 删除；`Ctrl/Cmd+C/V` 复制粘贴节点；`Esc` 取消选择/关闭菜单。
- **创建菜单**：画布空白处双击或右键，弹出"添加文本节点 / 添加图片节点 / 添加视频节点"菜单（对齐截图二）；底部工具栏提供同等入口（手型、文字、图片、视频、上传、删除、清空）。
- **文件进入**：拖拽图片/视频文件到画布 → 在落点创建对应节点并入库；粘贴剪贴板图片同理。注意与全局 composer 的 document 级 paste/drop 监听做作用域隔离（见 §11 风险 4）。
- **连线**：节点左右两侧出连接点（hover 显示，见截图三图片节点两侧圆点），拖出贝塞尔曲线连接；连线可选中删除。非法连接（见 §8 规则）在拖拽时即以置灰/提示阻止。
- **深色模式**：画布跟随现有主题，V1 以深色为主视觉（点阵深底，对齐截图）。

## 6. 节点类型与创建

### 6.1 通用节点结构

```ts
type CanvasNodeBase = { id: string; kind: 'text' | 'image' | 'video'; x: number; y: number; w: number; h: number; createdAt: number }
type CanvasTextNode  = CanvasNodeBase & { kind: 'text';  text: string; fontSize?: number }
type CanvasImageNode = CanvasNodeBase & { kind: 'image'; imageId?: string; taskId?: string; aspectLocked?: boolean }
type CanvasVideoNode = CanvasNodeBase & { kind: 'video'; videoId?: string; posterImageId?: string; taskId?: string }
```

要点：节点**只存资产 id（内容引用），绝不内嵌 dataUrl/base64**。图片走 `storeImageWithSize`（内容哈希去重），视频走 `putVideo`；节点渲染用缩略图（`ensureImageThumbnailCached` / `subscribeImageThumbnail`），大图仅在"大图"预览时经 `ensureImageCached` 取原图（含云端回落）。

### 6.2 文本节点

- 创建后即进入编辑态；双击再次编辑；自动按内容撑高，宽度可拖拽。
- V1 仅纯文本 + 字号（小/中/大），不做富文本。
- 作为上游连线到图片/视频节点时，其文本在生成时**追加进提示词**。

### 6.3 图片节点

内容来源四种：本地上传、从图片库选择（复用 `Tools/components/ToolImageSourcePicker.tsx` 的"上传或从图片库选择"面板与 `Tools/adapters/imageLibrary.ts` 的 `listToolImages/getToolImage/importToolImage`）、从画廊/对话"加入画布"、**空图片节点 + 画布聊天生成**。

空图片节点展示图片占位图标 + "空图片节点"文案；选中后弹出画布聊天（图片模式）。生成中展示流式预览（复用 `streamPreviews` 通道）与进度；完成后回填 `imageId`（多图输出时默认取第 1 张，其余提供"展开为新节点"入口，P1）。

### 6.4 视频节点

内容来源：本地上传、从视频库选择（`Tools/adapters/videoLibrary.ts`）、**空视频节点 + 画布聊天生成**（对齐截图一/二的核心流程）。

空视频节点展示摄像机图标 + "空视频节点"；选中后弹出画布聊天（视频模式，含模型/分辨率/时长/比例参数）。生成中展示轮询进度；完成后回填 `videoId + posterImageId`，节点内联可播放（hover 播放控制，复用 TaskCard 的视频封面/播放范式）。

## 8. 连线（边）语义与规则

- 连线方向：上游 → 下游（节点左侧为输入点、右侧为输出点），语义为"上游作为下游生成的输入/关联"。
- 三种节点两侧均可连接，任意类型间允许连线（2026-07-26 评审调整：不再限制方向组合，降低使用门槛）。
- 禁止：自连、重复连线、成环。
- 生成取材时按上游类型筛选：图片上游作为参考图，文本上游拼接提示词，视频上游 V1 忽略（不参与生成）。
- 生成时的取材规则：提交某节点的生成时，收集其**直接上游**——图片上游按连接顺序作为参考图（受能力上限截断），文本上游拼接到提示词后。
- **能力约束动态化（重要）**：图生视频仅 Gemini/Veo 支持且 `maxImages: 1`；Grok / 即梦的图生视频会直接抛错。连线与提交前必须经 `getVideoProvider(id).getCapabilities(profile)` 校验：能力不支持时，连线保留但在聊天面板给出明确阻断提示（"当前视频模型不支持图生视频，请切换模型"），并处理 Veo 的硬约束（1080p/4k 仅 8 秒、veo-3.0 1080p 仅 16:9——现有 `Sub2VideoComposerSettings` 已有依 capabilities 自动纠正的逻辑，直接复用）。

## 9. 画布聊天：全局聊天组件新增 canvas 类型

### 9.1 复用方式

按现有三层架构，**协议层与外壳组件零改动**，通过 toolId 机制新增类型：

1. 新建 `src/integrations/conversation/sub2CanvasTool.ts`：导出 `SUB2_CANVAS_TOOL_ID = 'canvas'` 的 `ConversationTool`。`submit` 内按目标节点 kind 分发：图片节点 → `submitTask({draft})`，视频节点 → `submitVideoTask({draft})`；提交成功后把 `taskId` 回写画布节点。
2. `conversationTools.ts` 注册该 tool 并 re-export ID。
3. `Sub2ImageConversationComposer.tsx` 增加 canvas 分支：画布路由分支下挂载同一个组件实例（全局仍然**同一时刻只有一个 composer 实例**，规避 `composerFocus.ts` 单 owner、document 粘贴/拖拽监听、`--composer-stack-clearance` 变量的冲突）。`toolId = SUB2_CANVAS_TOOL_ID`；`conversationId = canvas:${docId}:${nodeId}`（按节点隔离 running 状态与 AbortController，天然支持多节点并行生成）；placeholder 按节点类型显示"描述要生成的图片/视频内容"（对齐截图）。
4. 参数面板复用：图片节点 → `Sub2ImageComposerSettings`，视频节点 → `Sub2VideoComposerSettings`（模型、分辨率、时长、比例、积分展示均现成）。

### 9.2 交互流程（对齐截图一、二）

1. 选中空节点（或有内容节点的"重新生成"）→ 画布底部浮出聊天输入框，输入框与节点之间有视觉关联（选中描边同色）。
2. 上游连线的参考图以附件缩略图形式展示在输入框附件区（只读，不可在此增删——增删靠连线），文本上游以提示词前缀提示。
3. 输入提示词 → 发送 → 节点进入生成中态（输入框可继续操作其他节点）。
4. 任务完成 → 节点回填内容；失败 → 节点失败态 + 重试按钮，错误详情进"信息"。
5. `Esc` 或点击空白处收起输入框；节点保留各自的输入草稿（见 §11 风险 5 的草稿隔离方案）。

### 9.3 任务绑定与订阅

- `TaskRecord` 增加可选字段 `canvasDocumentId` / `canvasNodeId`（与既有 `agentConversationId/agentRoundId` 同构，IndexedDB 无 schema 约束，零迁移）。
- 节点组件订阅：`useStore((s) => s.tasks.find((t) => t.id === node.taskId))`，参照 `AgentImageTaskMessage` 渲染范式；流式预览走 `streamPreviews`。
- 刷新恢复：复用现有 `initAppState` 的任务恢复机制（fal/custom/video 轮询恢复），画布打开时按 `taskId` 反查任务态即可，无需额外恢复逻辑。
- 画布产生的任务**默认进入画廊**（保留统一的历史与云存储挂载点），任务卡标注来源"画布"；画廊增加来源过滤（仿 `isAgentTask` 增加 `isCanvasTask`）为 P1。

## 10. 数据结构与持久化

```ts
type CanvasDocument = {
  id: string
  title: string
  nodes: CanvasNode[]
  edges: { id: string; source: string; target: string }[]
  viewport?: { x: number; y: number; zoom: number }
  createdAt: number
  updatedAt: number
}
```

- **存储**：`src/lib/db.ts` 主库新增 `canvasDocuments` store，`DB_VERSION` 6 → 7（保持现有 `onupgradeneeded` 的"if not contains 再 create"风格；注意多标签页 `onversionchange/onblocked` 提示）。
- **写入策略**：对标本仓最新范式 `promptStudio/store/persistence.ts` —— 400ms 去抖、按文档 id 串行写、revision token 防陈旧覆盖、`flush/dispose` 在离开画布时兜底。
- **store 划分**：新建独立画布 store（`features/canvas/store/`），只保存"当前打开文档 + 视口 + 选中态"；视口/选中态不持久化（或仅 localStorage）。模块结构对标 promptStudio：`core/`（纯函数，配 boundary 测试）+ `ports/` + `adapters/` + `store/` + `components/`。
- **引用保护（最高优先级兼容项）**：`lib/imageReferences.ts` 的 `collectReferencedImageIds` 必须纳入画布文档引用的全部 `imageId/posterImageId`（照抄 `addPromptProjectImageReferences` 的异步 IDB 读取方式）；`features/videoLibrary.ts` 同步纳入画布 `videoId`。**此项不做，启动 GC 会静默删除画布图片。**
- **数据管理**：`dataManagement/dataTransfer.ts` 的 `clearData/exportData/importData` 与 `types.ts` 的 `ExportData` 同步覆盖 `canvasDocuments`，保证"清空/导出/导入"完整。

## 11. 兼容性分析与关键决策（摘要）

| # | 风险/耦合点 | 决策 |
| --- | --- | --- |
| 1 | 启动图片 GC（`initAppState` 全量枚举删除未引用图片） | 画布引用注册进 `collectReferencedImageIds` + 视频引用注册，随首版必做 |
| 2 | IndexedDB 升版（DB_VERSION 6→7）与数据导出导入 | 主库加 store，一并改 dataTransfer / ExportData |
| 3 | `AppMode` 深度耦合（persistence 会把未知模式压回 gallery） | 不扩张 AppMode，走 `/app/canvas` 独立路由分支 |
| 4 | 全局 composer 单实例假设（focus owner、paste/drop 监听、clearance 变量、`data-conversation-composer-dock` 选择器） | 画布分支挂载同一 composer 组件，保证同屏唯一实例；画布自身的拖拽入画布监听限定在画布容器内并在 composer 聚焦时让位 |

## 12. 技术选型：画布库

选用 **React Flow（`@xyflow/react` v12+，MIT）**：

- 与 React 19 兼容，内部同为 zustand，体积可接受；
- 节点即 React 组件（DOM 渲染），现有 TaskCard 式媒体展示、Tailwind 样式、缩略图订阅可直接进节点；
- 内置：无限视口、点阵背景、框选多选、连接点/贝塞尔连线、连接校验（`isValidConnection` 承接 §8 规则）、缩放控件、`onlyRenderVisibleElements` 视口裁剪、viewport 序列化；
- 备选对比：tldraw（自有协议需水印/商业授权，白板形态非节点连线）、Excalidraw（MIT 但手绘白板，无边语义）、Konva/Fabric（底层库，连线/选择/序列化全自研，仅节点上千时才有必要）。

## 13. 非功能需求

- **性能**：单画布 200 节点内交互流畅（60fps 拖拽）；节点渲染一律缩略图；开启视口裁剪；文档序列化体积 < 1MB（只存引用即可保证）。
- **可靠性**：写入去抖 + 离开时 flush；刷新后画布与生成中任务状态可恢复；多标签页打开同一画布 V1 不支持协同，后写覆盖并提示。
- **移动端**：可打开、浏览、双指平移缩放；编辑操作（连线、菜单）V1 不保证。
- **主题/无障碍**：跟随深色模式；菜单与节点操作可键盘触达（Esc/Delete/方向键微调 P1）。

## 14. 里程碑拆分

| 阶段 | 内容 | 验收要点 |
| --- | --- | --- |
| M1 画布骨架 | 路由 + 列表页 + React Flow 画布 + 三种节点创建/拖拽/删除 + 工具栏 + 持久化（含 GC 引用保护、DB 升版、数据导出导入） | 建画布→摆节点→刷新不丢、图片不被 GC |
| M2 节点能力 | 悬浮菜单 P0 项（信息/删除/存资产/云储存/下载/复制/替换/锁定比例/裁剪跳转/大图）+ 画廊/对话"加入画布"入口 + 连线与校验 | 三类节点菜单可用，画廊图一键入画布 |
| M3 生成闭环 | canvas tool + composer canvas 分支 + 空节点生成（图片/视频）+ 任务绑定三态 + 上游连线取材 + 能力约束提示 | 截图一/二的完整流程走通；Veo 图生视频成功 |
| M4 打磨 | 失败重试、错误详情、快捷键、性能核查、e2e | `npm run test:ci` 通过 |

## 15. 验收标准（V1 Definition of Done）

1. 从画廊与 Agent 对话均可进入/创建画布，"加入画布"链路可用。
2. 三种节点创建、拖拽、连线、悬浮菜单 P0 功能全部可用。
3. 空图片节点与空视频节点经画布聊天生成成功，图生视频（Veo）经连线参考图生成成功；不支持的模型给出明确阻断提示。
4. 刷新页面：画布内容、生成中任务状态、节点资产全部恢复；连续使用一周无资产丢失（GC 保护生效）。
5. 清空数据 / 导出 / 导入覆盖画布文档。
6. `npm run build && npm test` 通过，新增 core 纯函数与引用收集逻辑有单测；关键链路补 1 条 Playwright e2e（建画布→生成图片→刷新恢复）。
